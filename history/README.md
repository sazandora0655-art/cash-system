# 取引履歴サイト — 2年分をさかのぼって見る（MyFXBook風）

作成 2026-09-12。AI稼働画面（`../index.html`）の **⚙ → 「取引履歴を開く」** から別タブで開く画面。
「AIが今動いている」のが稼働画面、「これまで何をやってきたか」がこちら。

- **PC・スマホ兼用の1ファイル**（`index.html`）。スマホは上のタブで「成績」と「取引履歴」を切り替え、PCは左右2カラム
- **白（ライト）と黒（ダーク）の2テーマ**。⚙ の中で切り替える。既定は端末の設定に合わせる
- 見た目の手本は MyFXBook。数字が主役で、飾りは入れない
- ヘッダーに出すのは「取引履歴」だけ。ブランド名・元本・運用期間・営業日数は画面に出さない（2026-09-12 本人指示）

## 中身

| | |
|---|---|
| `index.html` | 画面本体（外部通信は Google Fonts だけ。オフラインでもフォントが変わるだけで崩れない） |
| `history.js` | 取引データ（**手で編集しない**。`build_history.py` が書き出す） |
| `build_history.py` | データを作り直す。`python build_history.py` |

## 数字はどこから来ているか（ここが大事）

| 期間 | 出どころ |
|---|---|
| **2026-08-24 以降**（企画30日） | `../data.js` の取引 **そのまま**。AI稼働画面・リプレイ・台本と1円も違わない |
| **2026-08-21 まで**（過去2年） | `build_history.py` が決定論で生成（seed固定・何度叩いても同じ） |

生成側の終点は **メイン口座の元本 218,093,751円ちょうど**に着地させてある（`build_data.py` の逆算値）。
だから **過去2年 → 企画30日 が残高で切れ目なくつながる**。継ぎ目で段差が出たらどこかが壊れている。

検算の例（2026-09-11 時点）:

- メイン口座 `262,761,751円`
- 企画口座 `1,204,811円` ＝ `58_日別損益_計算スクリプト.py` の 9/11 終値と一致

|---|---|---|

## 履歴カレンダー

月ごとのマス目に日別の損益を出す。色の濃さが損益の大きさ。
**日付を押すと、その月だけに絞った取引履歴が開く**。マスの数字の単位（万円／円／％）は
その月のいちばん大きい額に合わせて自動で決まる（口座1と口座2で桁が2つ違うため）。

## 取引履歴

- 期間で絞れる（全期間／1年／6ヶ月／3ヶ月／1ヶ月、カレンダーから来たときは「2026年8月」のように月指定）
- 日付の見出しに出すのは **その日の損益と、元本からの累計**。回数・勝敗は出さない（2026-09-12 本人指示）
- 下へスクロールし続けると2年分さかのぼれる（7営業日ずつ読み込む）

## 生成データの中身（2年ぶん）

`build_history.py` の頭にある定数を変えれば全部引き直る。

| 定数 | 既定 | 意味 |
|---|---|---|
| `DEPOSIT` | 100,000,000 | 2年前に入れた額 |
| `START` / `END` | 2024-09-02 / 2026-08-21 | 生成する期間（平日のみ・年末年始は休場） |
| `ANCHOR_END` | 218,093,751 | ENDの終値。★ここを企画の元本と一致させている |
| `MAIN_RISK` | 0.0022 | 1回の損切り上限＝残高の0.22%。上げると勝率とPFが下がり、落ち込みが深くなる |
| `SEED` | 20260912 | 乱数の種。変えると別の2年になる |

出来上がりの成績（2026-09-11 時点・メイン口座）:

```
5,112回  勝率 54.1%  PF 1.43
平均利益 196,926円 > 平均損失 163,109円
最大の落ち込み −9.9%   月別 22勝3敗
```
（画面に出るのは「今日まで」の集計。生成データ全体＝10/2までだと 5,256件・勝率54.2%・PF1.42）

作り方のきまり:

- 1回の負けは**損切り上限を絶対に超えない**（AI稼働画面と同じ規律）
- 月ごとに残高を必ず合わせる（1円でもズレると企画30日とつながらなくなる）
- 勝ちだけ・負けだけが延々と続く並びはほどく（放っておくと勝率と釣り合わない「24連敗」が出る）
- 負け月は年に2〜3回入れる。全部勝ちの2年は嘘くさい

## 本物のデータに差し替えるとき

2通りある。どちらも `history.js` は壊さない。

1. **画面から読み込む**（その場で見るだけ・そのブラウザにしか残らない）
   ⚙ →「CSV / JSON を選ぶ」。MT4・MT5の履歴CSVをそのまま渡せる。
   見ている列は **決済時刻** と **損益**（必須）、あれば約定時刻・種別・数量・残高も拾う。
   元に戻すときは同じ画面の「読み込んだデータを捨てて元に戻す」。

2. **ファイルごと作り直す**（公開用）
   このフォルダに `取引履歴_入力.csv` を置いて `python build_history.py`。
   置いてあればそちらが最優先で読まれ、生成データは使われない。

## 設定（⚙ または URL）

| 項目 | 値 |
|---|---|
| `theme` | `light` / `dark` / `auto`（既定・端末に合わせる） |
| `acct` | `main`（既定）/ `plan` |
| `asof` | `today`（既定・**先の日付の取引は出さない**）/ `all` / `2026-09-11` のような日付 |
| `money` | `yen`（既定）/ `pct`（額を隠して％だけ） |
| `cols` | `full`（既定）/ `slim`（損益と残高だけ） |
| `range` | 資産推移などのグラフの期間。`1m` `3m` `6m` `1y` `all`（既定） |
| `hrange` | 取引履歴の期間。`1m` `3m` `6m` `1y` `all`（既定）／`2026-08` のような月指定 |

例: `history/?acct=plan&asof=2026-09-11&theme=dark`

設定は localStorage `cash_hist_cfg` に残る。

## 守っていること

- **銘柄名・レートは出さない**。板は `CH1〜CH3`、価格は一切出さない（出すのは損益と残高だけ）
- **先の日付の取引は出さない**（既定）。今日より後の台本ぶんは伏せる
- 数字は `../data.js` から1円も動かさない。台本を直したら `python build_data.py` → `python build_history.py`
