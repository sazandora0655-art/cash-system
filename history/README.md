# 取引履歴サイト（2026-09-18 更新）

口座ごとに開始日を分ける。企画口座は2026年8月24日の100万円スタートから、メイン口座は従来の2024年9月2日からの過去2年分を含めて表示する。いずれもシミュレーション設定データ。

- `../data.js` の両口座の約定・決済時刻、売買、チャート、損益、決済後残高をそのまま使う。
- 元本は企画1,000,000円／メイン100,000,000円。累計損益は各元本を基準に計算。
- メインの9月1日より前は従来の履歴を維持（2026/8/21まで生成履歴＋8/24〜8/31の既存設定）。9/1以降は稼働画面のメイン口座データと一致。
- 両口座とも「全期間」で各開始日から選択した「今日」まで表示。期間フィルターは維持。
- ⚙内の「今日として扱う日付」で表示の終点を選択。その日終日までの決済を表示し、それ以降は除外する。
- 1ヶ月・3ヶ月等の期間は、選択した「今日」を終点に計算する。土日も指定可能。
- 稼働画面の履歴リンクから開くと、選択日と口座をURLで引き継ぐ。
- 口座切り替えは⚙内のプルダウン（企画口座／メイン口座）。画面上部の口座1・2ボタンは撤去。
- 日付・口座・テーマはブラウザに保存。URL指定があればそちらが優先。
- 白／黒テーマ、CSV／JSON読み込み、期間・勝敗・売買・CHフィルターは維持。

## スマホ幅の取引履歴（2026-10-03 午後）

さとる「スマホで見ると取引履歴のレイアウトがバグっている」。1行に 時刻・売買・ペア（板）・ロット・保有時間・損益・残高 の7つを並べると、ApexGrid（金額が9桁・ペア名・ロット小数2桁）は 375px 幅で最大443px、メイン口座も最大386px になり、枠（349px）からはみ出して残高が切れ、ページが横にずれていた（メインは差し替え前から）。

- 今は、**1行では枠に入りきらない口座・画面幅のときだけ、1件を2段で出す**（上の段: 売買・ペア・ロット・損益／下の段: 保有時間・残高）。入りきるかは、その口座の取引で各列いちばん長い値を集めた1行を、本物と同じ幅の見えない表に描いて決める（`needTwo()`）。取引履歴を開いた時・画面の幅が変わった時・条件を変えた時に決め直す。
- 結果（確認した幅 320・360・375・390・430・768・1280px）: ApexGrid とメインはスマホ幅（〜430px）で2段、タブレット・PCでは1行。企画はスマホでも1行（320px だけ2段）。どの幅でも全部の日の表が枠に収まり、横ずれなし。
- 1行のときの表の中身は前と1文字も同じ（PC幅で3口座とも公開中の版と突き合わせ済み）。「損益と残高だけ」の表示はいつも1行。
- **データを新しくしたいとき（Windows だけ。値動きデータがそこにしか無い）**:
  1. `python v2_8y_run.py <最後の日 例 2026.10.31> --lot-cap 1000 --out v2_8y_result_nocap_noguard.json`（システム関連の ツール フォルダで）
  2. `python v2_8y_page.py --src v2_8y_result_nocap_noguard.json --data-out v2_8y_data_nocap.json --no-html`
  3. `python build_apexgrid.py`（このフォルダで）
  4. 変えたファイル（`history/apexgrid.js` など）だけを鏡 `C:\Users\Owner\github\cash-system` にコピーして commit・push（`deploy.ps1` は企画・メインの台本データも作り直すので、この口座だけのときは使わない）
